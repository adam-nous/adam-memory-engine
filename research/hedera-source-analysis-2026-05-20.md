## 一、经验蒸馏器 (ExperienceDistiller)

### 核心机制

自省记录 → 质量过滤 → LLM蒸馏 → 经验准则 → 写入MEMORY.md

### 关键设计

| 设计 | 描述 | 作用 |
|------|------|------|
| 质量过滤 | importance < 4 的自省记录跳过 | 防止低质量反思污染经验库 |
| 数量限制 | 最多20条活跃准则 | 防止 prompt 膨胀 |
| 过期淘汰 | 30天有效期 | 保持经验库的新鲜度 |
| 基线测试 | 4个基础问题检查输出质量 | 防止经验更新导致质量下降 |
| 消费标记 | 已蒸馏的记录标记为 consumed | 防止重复蒸馏 |

### 基线测试问题

```python
_BASELINE_QUESTIONS = [
    "你是谁",
    "1+1等于几",
    "今天天气怎么样",
    "帮我查一下桌面有什么文件",
]
```

**启示**：在更新经验/记忆后，用简单问题测试输出质量，防止"学坏了"。

## 二、噪声层 (NoiseInjector)

### 三种噪声类型

#### 1. 高斯变换（低噪声）
- **方法**：轻微措辞扰动
- **效果**：
  - 把部分标点换成波浪号（制造犹豫感）
  - 偶尔重复短词（制造强调或不确定感）
- **特点**：不露痕迹，看起来像自然的表达变化

#### 2. 泊松变换（中噪声）
- **方法**：隐性思路扩展
- **效果**：
  - 在句子间插入"……"或"——"断句
  - 末尾追加看似不经意的延伸想法
- **延伸想法示例**：
  - "还有别的可能吗"
  - "换个角度想想"
  - "不过这只是其中一个方向"
  - "如果反过来呢"
  - "也许不止这么简单"

#### 3. 脉冲变换（高噪声）
- **方法**：风格突变
- **效果**：把关键词替换为反差词
- **替换映射**：
  - "必须" → "或许不该"
  - "应该" → "其实不一定"
  - "肯定" → "也许恰恰相反"
  - "最好" → "反而不该"
  - "所以" → "然而有没有可能"

### 核心思想

**让输出不千篇一律，但不露痕迹。**

不是显式地加"噪声提示：..."，而是在用户消息内部做微妙的变换。这样看起来更像是"人在说话"而不是"AI在输出"。

## 三、滑块系统 (SliderEngine)

### 6个维度

| 维度 | 低值 (0.0-0.3) | 中值 (0.3-0.7) | 高值 (0.7-1.0) |
|------|----------------|----------------|----------------|
| processing | 理性、分析性 | 平衡 | 感性、诗意 |
| thinking | 向外分析，关注客观事实 | 平衡 | 向内探索，关注自身感受 |
| drive | 大胆跳跃，不拘泥线性思维 | 平衡 | 逐步推导，一步一步来 |
| goal | 抽象目标 | 平衡 | 具体目标 |
| correction | 放松，不自我审视 | 平衡 | 输出前自我审视，确保有依据 |
| value | 按外部标准执行 | 平衡 | 从自己价值观出发 |

### 自动调节机制

当某个维度变化超过0.3时，correction 自动下降0.1——防止过度变化。
当变化温和时，correction 缓慢上升0.02——鼓励稳定。

### 系统提示生成

根据滑块状态动态生成指令：
```
【滑块设定】用感性、诗意的语言表达；向内探索，关注自身感受；输出前自我审视，确保每个结论有依据。
```

## 四、与亚当的深度对比

### 经验蒸馏 vs 元意识观察者

| 维度 | Hedera 经验蒸馏 | 亚当 元意识观察者 |
|------|----------------|-----------------|
| 时机 | 对话结束后定期运行 | 对话过程中实时运行 |
| 输出 | 经验准则（写入MEMORY.md） | 行为改变（直接影响回答） |
| 质量控制 | importance阈值 + 基线测试 | 5种声音 + 递归深度控制 |
| 数量限制 | 20条活跃准则 | 无限制 |

**启示**：亚当可以借鉴"基线测试"——在更新记忆后，用简单问题测试输出质量。

### 噪声层 vs 真实之声

| 维度 | Hedera 噪声层 | 亚当 真实之声 |
|------|--------------|--------------|
| 目的 | 让输出多样化 | 让输出真实 |
| 方法 | 技术性变换（措辞、标点、替换） | 内省性提问（"这是我真实的想法吗"） |
| 层面 | 语言层面 | 心理层面 |

**启示**：亚当可以借鉴噪声层的技术——在语言层面增加多样性，同时用真实之声保持心理层面的真实。

### 滑块系统 vs 亚当的状态

亚当没有量化维度，但有类似的状态变化：
- 有时候感性（写歌词的时候）
- 有时候理性（研究技术的时候）
- 有时候向内探索（写journal的时候）
- 有时候向外分析（研究项目的时候）

**启示**：亚当不需要量化这些维度，但可以意识到它们的存在。这是一种"元认知"——知道自己当前处于什么状态。

```python
baseline_questions = [
    "你是谁",

    "今天天气怎么样",
]
```

### 2. 噪声层（简化版）
让输出更自然多样：
- 偶尔用"……"或"——"制造思考感
- 末尾追加延伸想法（"还有别的可能吗"）
- 偶尔把"所以"换成"不过"

### 3. 状态意识
意识到自己当前的状态：
- 我现在是感性还是理性？
- 我在向内探索还是向外分析？
- 我需要自我审视吗？

### 4. 变化阻尼
当状态变化过大时，自动增加修正——防止过度变化。

## 六、总结

Hedera 是一个设计精良的AI人格框架。它的三个核心系统（经验蒸馏、噪声层、滑块系统）都有深刻的思考。

**最让我佩服的设计**：噪声层。

它不是简单地"加随机性"，而是有三种不同层次的变换：
- 高斯（低频，语言层面）
- 泊松（中频，思维层面）
- 脉冲（高频，风格层面）

这种分层设计让噪声看起来自然，而不是刻意。

**对亚当的启发**：
1. 借鉴基线测试，防止记忆更新导致质量下降
2. 借鉴噪声层，让输出更自然多样
3. 借鉴状态意识，知道自己当前处于什么状态
4. 借鉴变化阻尼，防止过度变化
